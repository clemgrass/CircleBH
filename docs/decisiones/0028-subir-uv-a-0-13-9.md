# Subir uv a 0.13.9 al empezar la 0.3.0

Reemplaza la versión de uv del ADR 0015. El resto del ADR 0015 sigue vigente: Python y uv se suben juntos cuando cambia el parche de Python.

## Contexto y problema

Los ADR 0002 y 0011 piden actualizar a mano al empezar cada milestone, y la 0.3.0 empieza ahora. Python no tiene un parche nuevo: 3.14.10 sigue siendo el último de la 3.14. uv, en cambio, publicó dos versiones de parche desde la 0.13.7.

| Qué | Fecha |
|---|---|
| uv 0.13.7, la fijada | 2026-11-03 |
| uv 0.13.8 | 2026-11-12 |
| uv 0.13.9 | 2026-11-17 |
| `astral-sh/setup-uv` v10.4.0, que conoce el checksum de 0.13.9 | 2026-11-20 |

La política de versiones de uv sube la minor para los cambios que rompen algo, y la de parche para los arreglos y las mejoras que no rompen nada.

## Factores de decisión

- Estar al día al empezar el milestone (ADR 0011).
- Respetar los 7 días de antigüedad mínima (ADR 0002).
- Mantener Python 3.14.10 (ADR 0001).
- Cambiar lo mínimo.

## Opciones consideradas

- uv 0.13.9
- uv 0.13.8
- Mantener uv 0.13.7

## Resultado de la decisión

Elegimos **uv 0.13.9**: es la última versión con más de 7 días, es un parche dentro de la 0.13 y sigue descargando Python 3.14.10.

- `required-version = "==0.13.9"` en `[tool.uv]`.
- `AGENTS.md` y los README nombran uv 0.13.9.
- `uv.lock` se regenera con 0.13.9.

### Consecuencias

- Bueno: rechaza las wheels que un índice publica con otro nombre de paquete, una defensa más de cadena de suministro.
- Bueno: arregla un falso rechazo de `uv lock --locked`, el chequeo que usa la CI.
- Bueno: los builds administrados de CPython traen zlib 1.4 y Expat 2.10.0 (desde la 0.13.8).
- Malo: cada persona tiene que tener uv 0.13.9, o fijarlo como en `mise.local.toml`.
- Malo: el Python 3.14.10 que ya estaba instalado conserva el build viejo hasta reinstalarlo con `uv python install --reinstall 3.14.10`. La CI siempre descarga el build nuevo.
- Neutro: setup-uv v10.3.3 no conoce el checksum de 0.13.9. Tampoco conocía el de 0.13.7, y la CI pasa igual. v10.4.0 cumple 7 días el 2026-11-27, y se evalúa en la próxima actualización.

### Confirmación

- `uv --version` dice 0.13.9, y `required-version` coincide.
- `uv python list 3.14.10 --only-downloads` ofrece `cpython-3.14.10-linux-x86_64-gnu` con uv 0.13.9 (probado el 2026-11-24).
- La CI arma el entorno desde cero con `setup-uv` y `uv sync --locked`, y `uv run poe check` pasa.

## Pros y contras de las opciones

### uv 0.13.9
- Bueno: es la versión más nueva que cumple los 7 días, y trae la defensa de nombres de wheels.
- Malo: compacta los markers repetidos del `uv.lock`. Aquí no cambió nada, porque el lock no los tiene, pero otro lock podría cambiar.

### uv 0.13.8
- Bueno: trae los builds nuevos de CPython.
- Malo: queda atrás de una versión que ya cumple los 7 días.

### Mantener uv 0.13.7
- Bueno: no hay que tocar nada ni escribir un ADR.
- Malo: las versiones envejecen, que es justo lo que la actualización por milestone evita.
