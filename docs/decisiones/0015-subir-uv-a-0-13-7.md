# Subir uv a 0.13.7 para poder descargar Python 3.14.10

Reemplaza la versión de uv del ADR 0002. El resto del ADR 0002 sigue vigente.

## Contexto y problema

El ADR 0001 fija Python 3.14.10 y el ADR 0002 fija uv 0.13.4. uv trae dentro del binario la lista de builds de Python que sabe descargar, y la 0.13.4 llega solo hasta la 3.14.8. Por eso, `uv python install 3.14.10` falla con `no download found for request cpython-3.14.10-linux-x86_64-gnu`. Lo mismo le pasaría a la CI, porque `setup-uv` lee `required-version`.

| Qué | Fecha |
|---|---|
| uv 0.13.4 | 2026-10-20 |
| Python 3.14.10 | 2026-10-25 |
| uv 0.13.6, que agrega CPython 3.14.10 | 2026-10-27 |
| uv 0.13.7 | 2026-11-03 |
| uv 0.13.8 | 2026-11-12 |

Probablemente, la verificación del ADR 0002 usó el Python 3.14.8 del sistema, y nunca tuvo que descargar la 3.14.10 (no verificado).

## Factores de decisión

- Mantener Python 3.14.10 y sus parches de seguridad (ADR 0001).
- Respetar los 7 días de antigüedad mínima (ADR 0002 y 0011).
- Cambiar lo mínimo.

## Opciones consideradas

- uv 0.13.7
- uv 0.13.6
- Bajar Python a 3.14.8 y mantener uv 0.13.4
- Instalar Python 3.14.10 fuera de uv, con mise o el sistema (no discutida)

## Resultado de la decisión

Elegimos **uv 0.13.7**: es la última versión con más de 7 días, sabe descargar 3.14.10, y estamos al inicio del milestone 0.1.0, cuando toca actualizar a mano.

- `required-version = "==0.13.7"` en `[tool.uv]`.
- `AGENTS.md` nombra uv 0.13.7.
- Desde ahora, Python y uv se suben juntos: antes de fijar un parche de Python, se revisa que las notas del release de uv lo agreguen ("Add CPython …").

### Consecuencias

- Bueno: se mantiene Python 3.14.10.
- Bueno: el entorno se puede armar desde cero en cualquier máquina y en la CI.
- Malo: es un ADR más por un cambio de versión.
- Malo: cada persona tiene que tener uv 0.13.7, o fijarlo como en `mise.local.toml`.

### Confirmación

- `uv --version` dice 0.13.7, y `required-version` coincide.
- `uv python find` devuelve un CPython 3.14.10 administrado por uv.
- La CI arma el entorno desde cero, con `setup-uv`, sin que Python esté instalado de antemano.

## Pros y contras de las opciones

### uv 0.13.7
- Bueno: es la versión más nueva que cumple los 7 días, y trae un arreglo de `uvx`.
- Malo: tiene una semana más de cambios que la 0.13.6.

### uv 0.13.6
- Bueno: es el salto mínimo que agrega 3.14.10.
- Malo: queda atrás de una versión que ya cumple los 7 días.

### Bajar Python a 3.14.8
- Bueno: no hay que tocar uv.
- Malo: pierde los parches de seguridad de 3.14.9 y 3.14.10, y hay que reemplazar el ADR 0001.

### Instalar Python fuera de uv (no discutida)
- Bueno: no hay que tocar ninguna versión.
- Malo: el entorno depende de cada máquina, y la CI no lo puede reproducir.
